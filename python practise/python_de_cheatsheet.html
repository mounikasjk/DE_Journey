Decorators — used constantly in Airflow, testing, and production code
import time, functools

# Timer decorator
def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.2f}s")
        return result
    return wrapper

@timer
def load_data(): time.sleep(1); return "done"
load_data()   # load_data took 1.00s

# Retry decorator — production DE pattern
def retry(n=3, wait=1):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*a, **kw):
            for i in range(n):
                try: return func(*a, **kw)
                except Exception as e:
                    if i==n-1: raise
                    time.sleep(wait)
        return wrapper
    return decorator

@retry(n=3, wait=2)
def call_api(): ...   # retries 3x on failure

Window Functions≈ OVER(PARTITION BY)
from pyspark.sql.window import Window

w = Window.partitionBy("dept").orderBy(
        F.col("salary").desc())

# RANK, DENSE_RANK, ROW_NUMBER
df.withColumn("rank",     F.rank().over(w))
df.withColumn("d_rank",   F.dense_rank().over(w))
df.withColumn("row_num",  F.row_number().over(w))

# LAG / LEAD
df.withColumn("prev_sal", F.lag("salary",1).over(w))
df.withColumn("next_sal", F.lead("salary",1).over(w))

# Running total — SUM OVER ORDER BY
w2 = Window.partitionBy("dept")\
            .orderBy("date")\
            .rowsBetween(Window.unboundedPreceding, 0)
df.withColumn("running_total", F.sum("sales").over(w2))

# Top N per group
df.withColumn("rn", F.row_number().over(w))\
  .filter(F.col("rn") <= 3)          # top 3 per dept

with DAG(
    dag_id="sales_etl",
    default_args=default_args,
    schedule_interval="0 6 * * *",   # 6am daily
    start_date=datetime(2024,1,1),
    catchup=False,                    # don't backfill
    tags=["sales","etl"],
) as dag:

    extract = PythonOperator(
        task_id="extract",
        python_callable=extract_fn,
    )
    transform = PythonOperator(
        task_id="transform",
        python_callable=transform_fn,
    )
    load = BashOperator(
        task_id="load",
        bash_command="python load.py",
    )

    extract >> transform >> load  # dependency

09 DE Design Patterns Idempotency · SCD · Partitioning · Backfill · Lambda/Kappa
Idempotent ETL Pattern — safe to re-run, no duplicates
# BAD — INSERT every run creates duplicates
df.to_sql("sales", con, if_exists="append")

# GOOD — MERGE / upsert pattern (idempotent)
# PySpark: use MERGE INTO Delta
# Pandas: merge then deduplicate before writing

# Idempotent S3 write — overwrite same partition
df.write.mode("overwrite")\
  .partitionBy("year","month","day")\
  .parquet("s3://bucket/data/")
# Same day re-run overwrites same partition only
Partitioning Strategy
# S3 / Parquet partition path pattern
# s3://bucket/table/year=2024/month=01/day=15/

# Pandas — write partitioned
df.to_parquet("s3://out/",
    partition_cols=["year","month"])

# PySpark — write partitioned
df.write.partitionBy("year","month")\
   .parquet("s3://out/")

# Read with partition pruning
df = spark.read.parquet("s3://out/")\
          .filter(F.col("year")==2024)
# Spark reads ONLY year=2024/ folder

# Good partition columns:
# ✓ date/time (year/month)
# ✓ region, country
# ✗ user_id (too many partitions)
# ✗ timestamp (infinite cardinality)
Architecture Patterns
# Lambda Architecture
# Batch layer   → process all historical data (Spark)
# Speed layer   → process recent data (Kafka/Flink)
# Serving layer → merge both for queries
# Downside: maintain TWO codebases

# Kappa Architecture
# Single streaming layer handles EVERYTHING
# Reprocess history by replaying from Kafka
# Simpler but harder to debug

# Medallion Architecture (Databricks)
# Bronze → raw ingest (no transforms)
# Silver → cleaned, deduplicated, typed
# Gold   → aggregated, business-ready

# When to use what
# Batch     → daily reports, DW loads
# Streaming → fraud, real-time dashboard
# Micro-batch → 5-min SLA, Spark Structured

Top interview questions + one-line answers
QuestionAnswer (say this)
repartition() vs coalesce()?repartition = full shuffle, increases or decreases. coalesce = no shuffle, only decreases. Use coalesce to reduce before write.
Lazy evaluation in Spark?Transformations (filter, select) build a plan but don't execute. Actions (count, show, collect) trigger execution. Enables optimization.
broadcast join when?When one DataFrame is small (<100MB). Sends small table to all executors, avoids expensive shuffle.
Data skew solution?Salting — add random suffix to skewed key, join, then aggregate again to merge salted results.
Idempotent pipeline?Re-running produces same result. Use MERGE/upsert instead of INSERT, overwrite same partition, add unique constraint check.
SCD Type 2?Keep history — add effective_date, end_date, is_current. New record inserts new row, old row gets end_date and is_current=false.
Exactly-once vs at-least-once?At-least-once: may duplicate on retry (use dedup). Exactly-once: harder, needs idempotent writes + offset tracking.
Delta Lake ACID?Atomicity (all or nothing), Consistency (constraints), Isolation (concurrent writes safe), Durability (committed = persisted). Implemented via transaction log.
Parquet vs CSV?Parquet: columnar, compressed, schema-aware, predicate pushdown, 10x faster reads. CSV: human-readable, no schema. Use Parquet for all DE work.
Airflow catchup=True risk?If start_date is old, Airflow backfills ALL missed runs at once. Can overwhelm system. Use catchup=False for new DAGs.
Common Gotchas
# 1. Pandas modifies copy, not original
df2 = df[df["x"]>5]
df2["y"] = 1   # SettingWithCopyWarning!
# Fix:
df2 = df[df["x"]>5].copy()

# 2. Spark collect() on large data = crash
df.collect()    # pulls ALL data to driver
df.show(20)    # safe — only 20 rows

# 3. String comparison is case-sensitive
df[df["dept"]=="de"]   # misses "DE"
df[df["dept"].str.upper()=="DE"]  # correct

# 4. Mutable default arguments
def bad(lst=[]):  # same list reused!
    lst.append(1); return lst
def good(lst=None):  # correct
    if lst is None: lst = []
    lst.append(1); return lst

# 5. Integer division
7 / 2   # 3.5  (float division)
7 // 2  # 3    (integer division)
